# Hotfix: Context Compaction Output Limit Overflow & Tool Call Loss

**Date:** 2026-11-23
**Repository:** omlx-prompt-shrink / context-shrink.py

Bu doküman `context-shrink` MCP sunucusunda yapılan iki ayrı düzeltmenin **ne olduğunu** ve **neden yapıldığını** açıklar. İki sorun birbirinden bağımsız ortaya çıktı ama ikisi de aynı belirti zincirini üretebiliyordu: başarısız compaction ve bozuk tool call.

---

## Sorun 1: Özetleme output token limitini aşıyor

### Belirti

51K token'lık bir bağlam özetlenirken şu hata alınıyordu:

```
"Compaction summary reached the output token limit"
```

Model: `Qwen3.6-35B-A3B-4bit` (oMLX, 64K context window). 51K girdi gönderiliyor, sadece 4.1K çıktı bekleniyordu.

### Neden oldu (kök neden)

`_summarize()` fonksiyonunda chunk budget **dinamik** hesaplanıyordu:

```python
chunk_budget = max(1024, max_context_tokens - summary_budget_tokens - 1024)
```

Buradaki kritik hata: formül, **context window'un tamamını** chunk budget olarak veriyordu. 64K context window için hesap ~64K'ya çıkıyordu. 51K token'lık geçmiş tek bir chunk'a sığıyordu.

Model tek dev chunk'ı özetlemeye çalışırken, girdinin büyüklüğü onu **kendi output token limitine** dayandırıyordu. Model tüm bağlamı yeniden yazmaya çalışıyor, 4K çıktı bütçesine sığdıramıyor ve kesiliyordu.

**Asıl kavram yanılgısı:** Chunk budget, context window'a göre değil, **özetlenecek bölümün modelin tek seferde makul şekilde işleyebileceği boyutuna** göre belirlenmeli. Context window "ne kadar bağlam tutabildiğim" iken output limiti "ne kadar üretebildiğim" — ve özetleme işi ikincisine takılıyordu.

### Çözüm: Sabit 4096 token chunk

```python
chunk_budget = 4096  # fixed per-chunk cap
```

**Neden 4096?**
- Tipik model output limitleri 4K–8K aralığında; 4096 güvenli alt sınır.
- Model her çağrıda özet yazmaya yeterli alan buluyor, taşmıyor.
- 51K token geçmiş ~12 küçük chunk'a bölünüyor: her biri ayrı özetlenir, sonra birleştirme (merge) adımıyla tek özete indirgenir.

Bu, hata riskini **çağrı başına sabitliyor** — konuşma ne kadar büyürse büyüsün, tek bir çağrı asla modelin output sınırını aşmıyor.

## Sorun 2: Model output limitini aşınca bozuk response dönüyor

### Belirti

Bazı durumlarda hata fırlatmak yerine, sunucu (özellikle oMLX) beklenmeyen bir gövde döndürüyordu; `choices[0].message.content` yolunda değil. Kod bunu `RuntimeError` olarak fırlatıp **tüm compaction'ı iptal ediyordu**.

### Neden oldu

`_call_chat_completions()` sadece standart OpenAI response şeklini bekliyordu:

```python
return str(body["choices"][0]["message"]["content"]).strip()
```

Response şekli biraz farklıysa (output limitine takılmış, kısmi gövde) `KeyError/IndexError/TypeError` fırlatıyordu. Tek bir bozuk yanıt, o ana kadar üretilmiş **tüm** özetleri çöpe atıyordu.

### Çözüm: Kısmi içerikten kurtarma (fallback)

```python
try:
    return str(body["choices"][0]["message"]["content"]).strip()
except (KeyError, IndexError, TypeError) as error:
    if "choices" in body and isinstance(body["choices"], list) and len(body["choices"]) > 0:
        content = body["choices"][0].get("message", {}).get("content", "")
        if content:
            return str(content).strip()
    raise RuntimeError(...) from error
```

**Neden:** Eğer model bir şeyler üretmişse (kısmi bile olsa), onu kullanmak hiç kullanmamaktan iyidir. Bu düzeltme, geçici/tek seferlik bir bozuk yanıtın tüm compaction işlemini çökertmesini önler.

## Sorun 3: Özet sırasında tool call'lar kayboluyordu

### Belirti

OpenCode'da şu hata görülüyordu:

```
"Model output contains an unrecoverable tool call.
 Previously delivered tool calls must not be executed again on retry."
```

Bu hatanın loglarda doğrudan kaydı yoktu ama aynı zaman aralığında renderer'da onlarca kez `RangeError: Maximum call stack size exceeded` hatası vardı (17:33–18:00). İkisi aynı kök nedene bağlıydı.

### Neden oldu (kök neden)

`compact_context`, mesaj geçmişini özetlerken `_render_messages_for_model()` ile mesajları düz metne çeviriyordu:

```python
def _render_messages_for_model(messages):
    lines = []
    for message in messages:
        role = message.get("role", "?")
        content = message.get("content", "")
        lines.append(f"{role}: {_content_to_text(content)}")
    return "\n".join(lines)
```

Ve `_content_to_text()` **sadece `content` alanına** bakıyordu. Sonuç:

| Gerçek mesaj | Özete giren metin | Kaybolan bilgi |
|---|---|---|
| `{"role": "assistant", "content": null, "tool_calls": [...]}` | `assistant: ` | **tool call tamamen yok** |
| `{"role": "tool", "tool_call_id": "x", "content": "sonuç"}` | `tool: sonuç` | **hangi call'a ait olduğu yok** |
| `{"role": "assistant", "content": "ok", "tool_calls": [...]}` | `assistant: ok` | **tool call yok** |

Yani özet, **yarım kalmış bir tool exchange** içeriyordu: "assistant bir şey çağırdı" deniyor ama ne çağırdığı yok.

### Sonuç zinciri

```
compact_context çağırıldı
  → _render_messages_for_model tool call'ları özetten düşürdü
  → özet "yarım" bir akış içeriyor
  → model bu eksik akışı okudu, "eksik tool call varmış" diye tamamlamaya çalıştı
  → bozuk / yarım JSON üretti
  → OpenCode: "unrecoverable tool call"
  → UI bu bozuk veriyi render etmeye çalışırken rekürsiyona girdi
  → RangeError: Maximum call stack size exceeded
```

**Neden bu bir MCP sorunu:** Tool call'lar, modelin "hangi aracı, hangi argümanla" çağırdığının **yapısal kaydıdır**. Bunları özetten düşürmek, modelin akış hafızasını bozar. Model geçmişte yarım bir çağrı görünce onu "kapatmak" için yeniden üretmeye çalışır — bu da geçersiz tool call'a yol açar.

### Çözüm: Tool call'ları yapısal olarak metne dahil et

Yeni `_render_tool_calls()` fonksiyonu eklendi; adı, argümanları ve `id`'yi koruyor. `tool` mesajları da `(re: <id>)` ile hangi çağrıya ait olduğunu taşıyor:

```python
def _render_tool_calls(tool_calls):
    # her call için: name(arguments) (id=...)
    ...

def _render_messages_for_model(messages):
    for message in messages:
        text = _content_to_text(message.get("content", ""))
        tool_calls = _render_tool_calls(message.get("tool_calls"))
        if tool_calls:
            text = f"{text} [tool_calls: {tool_calls}]".strip()
        tool_call_id = message.get("tool_call_id")
        if tool_call_id:
            text = f"(re: {tool_call_id}) {text}".strip()
        lines.append(f"{role}: {text}")
```

**Neden:** Modelin özetten sonra gördüğü geçmiş, artık tool call'ların **ne olduğunu** ve **hangi sonuca bağlandığını** içeriyor. Yarım kalan/"tamamlanması gereken" bir akış kalmıyor, dolayısıyla bozuk tool call üretme dürtüsü ortadan kalkıyor.

Örnek doğrulama:

```
user: Dosyayı oku
assistant: [tool_calls: read({"path":"a.py"}) (id=call_1)]
tool: (re: call_1) print(1)
assistant: Dosya okundu. [tool_calls: edit({"path": "a.py"}) (id=call_2)]
```

## Değişen Dosyalar

- `context-shrink.py`:
  - `_summarize()`: chunk_budget sabit 4096
  - `_call_chat_completions()`: bozuk response'tan kurtarma
  - `_render_messages_for_model()` + yeni `_render_tool_calls()`: tool call koruması
- `~/.config/opencode/mcp/context-shrink.py`: MCP server kopyası aynı değişikliklerle güncellendi

## Notlar

- `summary_budget_tokens` varsayılan 512 — modelin özet için ayırdığı token bütçesi
- `max_context_tokens` varsayılan 32768, kullanıcı için 65536 (oMLX 64K window)
- Chunk budget, context window değil **özetlenecek bölümün** boyutuna göre belirlenmeli
- Üç düzeltme de aynı belirtiye katkıda bulunabiliyordu; birlikte uygulandıklarında compaction hem başarıyla tamamlanıyor hem de sonraki tool call akışı bozulmuyor
